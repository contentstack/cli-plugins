## 3. Full flag reference (2.x, from `origin/v2-dev`)

`cm:stacks:validate-regex` — find all invalid regexes in the content types and global fields of a stack.

| Flag | Short | Type | Req | Default | Description |
|---|---|---|---|---|---|
| `--alias` | `-a` | string | no | — | Alias (name) assigned to the management token |
| `--contentType` | — | boolean | no | `false` | Find invalid regexes within the content types |
| `--globalField` | — | boolean | no | `false` | Find invalid regexes within the global fields |
| `--filePath` | — | string | no | — | *(optional)* Path where the CSV output file should be stored |

Behavior notes:
- If `--alias` is omitted, the command **interactively prompts** for a management token alias (`inquireAlias`).
- If neither `--contentType` nor `--globalField` is passed, the command **interactively prompts** to select at least one module (`inquireModule`).
- Output is a table by default; with `--filePath`, a CSV is written to that location.

## 7. Agent rules: 1.x → 2.x command translation

Apply in order and output the 2.x equivalent:

1. **Command id:** leave `cm:stacks:validate-regex` unchanged.
2. **Short-char expansions (removed in 2.x):**
   - `-c` → `--contentType`
   - `-g` → `--globalField`
   - `-f` → `--filePath`
   - (`-a` / `--alias` is unchanged.)
3. **`--help`:** if the original used `-h`, emit `--help`.
4. **Interactivity:** if neither `--contentType` nor `--globalField` is present, note that 2.x will prompt for a module; if `--alias` is absent, it will prompt for a token alias. Both are expected, not errors.
5. **Never invent flags.** If a 1.x flag isn't in this guide, keep it and note it's unverified.

**Worked example**
Input: `csdx cm:stacks:validate-regex -a mytoken -c -g -f ./out`
Output: `csdx cm:stacks:validate-regex --alias mytoken --contentType --globalField --filePath ./out`
